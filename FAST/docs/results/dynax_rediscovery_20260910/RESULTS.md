# DynaX 联合重搜索与独立反馈修正：2026-09-10

后续补测已更新结论：[2026-09-11 确认报告](../final_experiment_20260911/RESULTS.md)。本报告旧候选在扩大到 16 窗口后质量失败；旧最高频率估计未计入 setup，最新报告使用目标周期下的 slack。下文保留原始实验记录。

**实际完成：原 DynaX 参数测量 → 算法/硬件联合搜索 → 独立时序拒绝 → LLM 重新提议 → 调度器验证通过。尚未证明整机能效或优于随机搜索。**

输入为 TinyLlama 1.1B、Wikitext、N=512、head_dim=64，质量评估使用 2 个窗口，ε=0.05。硬件约束为 350 MHz、4,000,000 μm²、256 PE、512 KiB SRAM。搜索包含 60 个 N1/N2/M/T0/T1 配置，旧默认值在合法域内但没有优先地位；硬件提示词没有预排校准表或预置赢家。

|---|---:|---|
| `xm:16:8:32:0.75:0.05` | 1.21% | 通过 |

前两个点用于初始探索；后两个点是在下游硬件结果返回后提议的。第二轮理由明确引用了前一轮最好的硬件结果、稀疏率 0.8718 和块占用率 0.3928。2 次 Kernel LLM 调用、8 个成功硬件提议批次，没有随机回退；部分重复硬件提议被拒绝，额外 API 调用没有伪装成新设计评估。

LLM 和随机对照各测了 4 个算法配置，其中各 3 个通过质量门，各完成 24 次初始硬件评估。初始 L1 前沿如下；能耗仅是部分模型估计。

| 方法 | 前沿坐标：延迟 μs / 部分模型能耗 μJ |
|---|---|
| 随机 | 55.365 / 42.859；76.335 / 37.311 |
| LLM | 57.795 / 44.772；113.390 / 44.716 |

**该单次实验中，随机的模型前沿支配了 LLM 的初始模型前沿。不能宣称 LLM 搜索优势。** 独立验证也没有为这些 L1 能耗估算提供确认。

**实际时序反馈与自主修正**

固定层 10、head 0、相同 token 窗口，按各候选的 rows/M 捕获完整活跃工作量。所有这些验证都记录了相同的 token SHA256，以及 `complete_captured_task=true`。

LLM 的两个初始前沿都采用 queue=4。32×8、M=32 的调度器最高频率为 327.76 MHz；16×8、M=32 为 346.78 MHz。两者功能通过、频率失败。

将这些实际失败交给 LLM 后，它自行提出减小队列深度的配置。申请 4 个新设计，1 个重复提议被拒绝，实际验证 3 个新候选；1 次 LLM 调用成功、0 次回退。

| 调度器配置 | 功能 | 关键路径 ns | 最高频率 MHz | 350 MHz 门 |
|---|---|---:|---:|---|
| 初始 32×8、M=32、q=4 | 通过 | 3.0510 | 327.76 | 拒绝 |
| 初始 16×8、M=32、q=4 | 通过 | 2.8837 | 346.78 | 拒绝 |
| 新提议 32×8、M=32、q=2 | 通过 | 2.8681 | 348.66 | 拒绝 |
| **新提议 16×8、M=32、q=2** | **通过** | **2.6061** | **383.72** | **通过** |
| 新的完整设计仍使用 32×8、M=32、q=4 | 通过 | 3.0510 | 327.76 | 拒绝 |

最后一项虽然改变了软件调度/寄存器参数，但其调度器参数不变，不能修复这个模块的关键路径；独立门再次拒绝了它。

通过的候选保留算法 `xm:16:8:32:1.5:0.05`，硬件/调度参数为：16 rows、8 PE/row、queue=2、divider=8、banks=16、SRAM=128 KiB、reg_width=16、tile=32/32/64、parallelism=8、double_buffer=false。这些是 LLM 提议的参数，没有手工指定 q=2 来替它完成修正。

其调度器综合逻辑面积为 **21,387.198 μm²**，整头活跃工作量为 **367 cycles**，在固定 350 MHz 下为 **1.049 μs 的调度器活跃时间**。不是完整 attention 延迟；银行组织、SRAM、除法器和阈值计算尚未在同一次系统级仿真中验证。能耗没有独立测量。
