# RQ1 四算法核对与补完计划

核对时间：2026-09-17 UTC。本文是既有实验的审计与后续方案，不代表新实验已启动或完成。

> Can FAST generalize across diverse dynamic sparse-attention algorithms and automatically derive effective full-stack designs without algorithm-specific manual optimization?

## 当前实际证据

四个算法契约是 DynaX X:M、Block N:M、Global Top-K、Sanger-style probability threshold。前两种分别采用自适应块内配额和固定块内配额；Top-K 使用全行排序；threshold 使用概率阈值。固定配额算法的选择索引依赖输入，不意味着保留数量也动态变化。当前 Sanger 只实现概率阈值行级契约，不能称为原论文完整加速器复现。

| 算法及来源 | 外层轮次 | 独立验收 | 当前可用结果 |
|---|---|---|---|
| Global Top-K，v1 | R1–R5均有PPA，R4时序失败 | R5通过 | k=15；留出RMSE 2.0984%；300 MHz；230 ns；19154.926 µm²；6.234093 mW；1.433841 nJ/query；0.697427 Gqueries/J |
| Sanger threshold，extended v2 | R1/R2有PPA，R3构建失败终止 | R1通过 | threshold_256=3；留出RMSE 3.8868%；300 MHz；73.333 ns；74779.516 µm²；23.300078 mW；1.708672 nJ/query；0.585250 Gqueries/J |
| DynaX，recovery v3 | R1/R2/R4有PPA；R3失败后回退；R5物理流程超时 | 未执行最终验收 | R1/R4：n1=8,n2=7,t0_quarters=2,t1_quarters=0；校准/选参验证最差RMSE 0.2364%；300 MHz；200 ns；132392.988 µm²；47.665570 mW；9.533114 nJ/query；0.104898 Gqueries/J |
| Block N:M，extended v2 | R1 RTL通过，PPA超时后终止 | 未完成 | n=7,m=8；留出RMSE 3.7754%；RTL 100/100、68拍；没有可用完整物理PPA |

这些是不同开发批次的最好已有证据，不能解释为同一版本下的成功率：有独立合格设计的算法为2/4，有完整物理PPA的为3/4，有RTL E2E通过记录的为4/4。只有Top-K完成五个外层设计轮次。

功耗为统一活动率0.1下的布线后工具估计；面积为标准单元面积，不是die面积。Top-K/Sanger/Block的留出集是seed=20260916、4096随机样本；DynaX恢复实验的预注册最终测试是seed=2026091801、8192样本，尚未执行，故RMSE列不能混作相同测试集。

### Critic 的实际作用

- Top-K：R1→R5延迟283.333→230 ns，约下降18.8%；能效0.407649→0.697427 Gqueries/J，约提升71.1%。这是完整流程单次运行的改善，尚不能归因于Critic，因为没有等预算OFF对照。
- Sanger：R2将阈值3降至2，留出RMSE改善到2.3997%，但延迟73.333→140 ns、能效0.585250→0.278192；在误差≤5%约束下，R1支配R2。R3在ExpStage行为/流水线测试处失败，没有新增Pareto点。
- DynaX：Critic实际介入，R3失败回退有效；R2时序失败，R4恢复R1指标。R5 RTL为56拍，尚不能证明300 MHz可行或能效改善。
- Block N:M：本次首轮PPA失败发生在Critic入口之前，没有一次完整Critic迭代。

### 卡点核对

1. Block N:M已通过100/100端到端RTL用例并完成综合；Hammer par超出3600秒工具时限。末尾详细布线仍有5个DRC，不能只增加超时就保证成功，也不能用综合面积41755.616 µm²代替完整PPA。
2. Sanger R3反复出现ExpStage功能不匹配。模型多次推断golden错误，但尚无独立证据支持该判断；需要先用冻结输入的捕获/输出时刻、宽位有符号中间值进行诊断，不得按模型建议修改可信测试答案。
3. DynaX在第5轮物理设计时触发6小时作业时限，未生成summary.json。后处理仅因正常退出被标记COMPLETED，实际results.json为aborted_without_summary并跳过独立验证。报告绘图环境另缺matplotlib。

## 补完顺序

### 第一阶段：回收已有成果，明确标注为开发恢复

1. DynaX：对未改动的R1/R4可行设计补做预注册独立精度、额外RTL种子及布线后门级功能；对R5原样设计续做物理评估，再根据实际结果进入Critic。单独保存恢复记录，不伪造原作业已正常完成或新增第6轮优化。
2. Block N:M：保留现有通过的RTL，先诊断路由不收敛/超时；通过通用物理后端的可审计重试、资源与预算策略恢复PPA。若改变物理参数，记录为新候选；仍失败则把路由证据送入Critic/Compiler，而不是直接终止全程。
3. Sanger：保留独立合格的R1；将通用失败回退、精确时序诊断、未改模块复用应用到后续恢复，使一次失败不丢失既有可行设计。优化跨模块延迟时由Compiler更新契约，不能只让UArch违反固定延迟。
4. Top-K：保留当前成功证据，待统一版本冻结后参加正式重跑。

恢复前优先修复通用机制：逐阶段持久化与断点恢复、区分工具故障和候选不可行、对PPA失败调用Critic、没有summary也能后验证已完成轮次、失败候选不覆盖Pareto档案、报告运行环境检查。恢复工具执行不应被统计成新的算法优化轮次；改设计或配置则消耗候选预算。

### 第二阶段：冻结同一协议，四算法正式重跑

- 四算法使用同一代码提交、只读模板目录、模型设置、提示词结构、规划/修复/工具预算。算法专属输入限于算法定义、合法参数空间、可信数学与测试契约，以及实验前声明的参考映射。
- DynaX恢复时追加的两个历史FAST生成组件属于新增先验。若用于正式主实验，应在运行前对四算法统一开放并登记来源；不得只给某个算法临时加入针对失败的实现，再宣称未做算法专属人工优化。
- 保持统一300 MHz（满足用户>250 MHz要求）、单元面积≤200000 µm²、setup/hold≥0、route DRC=0、相对输出RMSE≤5%。统一校准与选参验证集；主实验最终测试集预注册且不反馈搜索。开发中已查看的留出数据不能继续宣称新实验的独立测试。
- 最多5个外层候选，含R1初始设计。失败候选计入预算；报告尝试数、完成E2E/PPA数、Critic调用数分别统计，不要求凑出5个成功点。
- 建议每算法至少3次独立Agent运行，固定工作负载划分，改变生成随机种子；共12次运行、至多60个候选。报告达到可行设计的比例、首次可行耗时、tokens、最佳点与运行间差异。不同随机种子不保证完全独立，需保留实际调用与重复性信息。
- 每算法分别绘制latency–energy-efficiency Pareto，保留所有候选及失败类型；只有通过最终验收的点计入最终前沿。跨算法汇总可以展示，但不能代替各算法相对自身对照的改进。

### 第三阶段：证明“effective”和“without manual optimization”

主RQ1至少增加同输入、同库、同预算的固定模板/仅参数搜索对照。另增加同工作负载、数值格式和PPA条件的dense参考，报告稀疏方法是否确有硬件收益；硬件生成成功不等于加速成功。若没有专家优化基线，只能声称在定义的测试范围内无需逐算法人工改RTL，不能声称性能替代专家优化。

Critic ON/OFF应另列消融：相同初始设计、相同候选与生成/工具预算，OFF明确采用预注册的候选策略（如重新采样或随机合法配置），不能只运行一次就与ON的5轮比较。该消融解释改善来源，不能由Top-K单条改善轨迹代替。

当前统一活动率的功耗分析不能验证“少选若干key就减少数据相关开关功耗”的推断。必须查看实际生成的数据通路是否跳过计算/门控，以及面积、周期或活动变化；条件允许时加入相同代表性输入的波形驱动功耗。当前能量定义是工具平均功耗×单query延迟；若测试流水吞吐能效，需要另测稳态吞吐并按throughput/power计算，不能把两种口径混用。

## 规模与论文措辞

目前四算法统一工作负载为16 keys、head_dim=2、value_dim=1的合成量化decode行；这是可验证的机制适配实验。Top-K最终仅6.25%稀疏率，DynaX当前可行点约1.64%（约73.83%查询全保留），尚不足以支持高稀疏率加速收益。Sanger独立留出稀疏率约36.34%，Block N:M为12.5%。

完成上述主实验后，至少再加一个较大规模及固定真实模型Q/K/V样本集；先验证公共契约、可信参考和工具容量，再运行Agent。否则论文结论应限定于这四种小规模稀疏机制。需要记录哪些模块新生成、哪些链接库、哪些仅适配接口，以及人工干预次数；透明的库复用符合库驱动设计，但不等于所有模块从零创造。

当前最准确结论：FAST已对四种稀疏机制产生通过RTL端到端测试的实现；其中Top-K与Sanger有独立合格物理设计，DynaX有待独立验收的可行物理设计，Block N:M物理流程尚未完成。跨算法统一实验、有效性对照及重复性仍待补齐。
