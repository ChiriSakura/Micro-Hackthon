本轮实验已完成：找到一个通过扩大质量检查的软件配置，完成对应调度器的真实 RTL 重放、综合与目标频率检查，并得到参数一致的硬件组件面积和功耗估算。**尚未得到通过全部约束的集成加速器，也没有完整 attention 的实测能效–延迟 Pareto 前沿。**

[结果图](results.png) · [可分享 PDF](results.pdf) · [机器可读汇总](summary.json) · [最终配置](final_design.json) · [最终调度验证](final_validation.json)

本轮使用 TinyLlama 1.1B intermediate-step-1431k-3T、原 DynaX 实现、Wikitext-2、序列长度 512、head dimension 64、FP32、seed=20260903。质量约束是相对 dense 的困惑度增幅不超过 5%。硬件目标为 350 MHz、256 个执行 PE 上限、512 KiB SRAM 上限、4 mm² 面积预算。工艺为 Nangate45 typical 预测库，结果为布局前估算，不是 DynaX 论文所用商业工艺或芯片测量。

**最后采用的确认配置**

| 项目 | 配置 |
|---|---|
| 软件稀疏策略 | `xm:16:8:32:0.75:0.05` |
| 动态保留数量 | 每 32 列块保留 0、8 或 16 列 |
| N1 / N2 / M | 16 / 8 / 32 |
| T0 / T1 | 0.75 / 0.05 |
| 软件评估精度 | FP32；`is_quant=false` |
| 软件 tile Q/K/D | 32 / 32 / 64 |
| 调度并行度、双缓冲 | 8；关闭 |
| 执行阵列 | 16 行 × 8 PE = 128 个 PE；16 位 Q8.8 |
| 执行寄存器宽度 | 16 个标量；本地列选择位宽 5 |
| 预测阵列组件 | 16 行、D=64，4 位操作数、1:2 pruning |
| TopK 组件 | 每行一个 M=32、N=16 的选择器，共 16 个 |
| BlockScheduler | 16 行 × 8 PE，M=32，queue depth=2 |
| 除法器组件 | 每行一个，8 级流水，共 16 个 |
| SRAM / 取数接口 | 128 KiB，16 个独立 bank，16 位/bank；每 bank 4096 项，16 路请求 |
| 目标时钟 | 350 MHz，周期 2.857143 ns |

这是**组件设计方案**。动态阈值分支在原 DynaX 软件中真实执行；现有 TopK、调度器、取数器、执行阵列还没有集成为同一个动态 X:M 系统。软件的 FP32 质量门也不能替代硬件 Q8.8 的端到端数值验证。

**扩大样本后的质量结果**

原来只有 2 个窗口的结果不足以决定最终配置。扩大到相同的前 16 个窗口后，旧 FAST 点、固定默认值与选定随机对照均超出 5% 限制：

| 方法 | 配置 | 困惑度 | 相对 dense 增幅 | 5% 门限 |
|---|---|---:|---:|---|
| Dense | 无稀疏 | 12.17459 | — | 参照 |
| 原 DynaX 默认算法 | 16/8/64，T=1/0.1 | 14.42229 | 18.46% | 失败 |
| 原 FAST 确认点 | 16/8/32，T=1.5/0.05 | 13.01581 | 6.91% | 失败 |
| 原随机搜索对照点 | 32/4/64，T=1.5/0.2 | 13.16790 | 8.16% | 失败 |
| **最终确认点** | **16/8/32，T=0.75/0.05** | **12.62505** | **3.70%** | **通过** |
| 另一原 LLM 提议 | 32/8/32，T=1.5/0.05 | 12.50544 | 2.72% | 通过 |

最终确认点在**后 16 个未用于选择的窗口**上，dense 困惑度为 7.73053，稀疏配置为 7.99024，增幅 **3.36%**；32 窗口合计增幅为 3.53%。32 窗口平均保留因果可见位置的 29.03%；若以整个含未来位置的方阵作分母，稀疏率为 84.97%，这两个分母不能混用。

确认策略事先使用前 16 个窗口的质量门，在合格的既有 LLM 提议中优先选较小 N1，以保留较小 TopK 容量，再用后 16 个窗口检查；没有根据后 16 个窗口重新选择。N1=32 的备选在后 16 个窗口也通过，增幅 3.21%。**这个选择是工程确认点，不是已证明的能耗–延迟 Pareto 最优点。**

算法配置来自之前的 LLM 提议，硬件来自 LLM 收到真实 STA 失败后的修正。本轮执行的是后续质量确认、硬件复用与独立工具验证，没有把这些脚本操作计作新的自主 LLM 提议。当前检查使用小样本同一模型，不能推广到任意模型或任务。

**调度器的独立 RTL 结果**

固定 layer=10、head=0，重放一个 N=512 输入的完整活跃 tile 工作量。最终配置包含 272 个活跃 tile。验证检查每周期公共计数器、总工作量守恒、所有入队工作排空与 Chisel 断言。

| 方案 | 执行 PE 数 | 调度活跃周期 | 350 MHz 下活跃时间 | 调度器逻辑面积 μm² | setup slack ns |
|---|---:|---:|---:|---:|---:|
| 固定基线 32×4，M=64，q=2 | 128 | 226 | 0.646 μs | 26,382.678 | +0.3870 |
| 原 FAST 16×8，M=32，q=2 | 128 | 367 | 1.049 μs | 21,387.198 | +0.2164 |
| **最终确认算法 + FAST 硬件** | **128** | **418** | **1.194 μs** | **21,387.198** | **+0.2164** |
| 随机对照 32×8，M=64，q=0 | 256 | 210 | 0.600 μs | 15,615.530 | +0.3496 |

以上均通过调度功能与目标频率检查。最终点的 418 周期**不是完整 attention 的延迟**：消费端假定每拍准备好接收，未覆盖计算、访存反压和整层执行。不同算法保留的工作量不同；不能用牺牲质量的基线周期证明有效加速。

最终点调度器关键路径到达时间为 2.6061 ns，计入 setup 后的频率估计约为 **378.68 MHz**。旧报告用 `1000/arrival` 得到 383.72 MHz，忽略了 setup；本轮已修正，验收直接使用 350 MHz 下非负 slack。最终阈值调整前后，调度器映射网表 SHA256 完全一致，确认面积与时序可以复用；新的工作量则独立重放。

**硬件组件面积和功耗**

面积由各组件分别综合后按实例数求和，再加独立 bank 组织的 fakeram45 宏模型。功耗使用 OpenSTA 的统一输入翻转率假设 α=0.10、duty=0.5、350 MHz，内部活动由工具传播；不是来自完整工作负载 VCD。

| 最终方案组件 | 面积 μm² | 功耗估计 mW，α=0.10 |
|---|---:|---:|
| RePE 执行阵列 | 399,842.688 | 454.637 |
| 预测阵列 | 372,245.454 | 50.420 |
| 16 个 TopK | 99,535.072 | 136.128 |
| 16 个流水除法器 | 86,588.320 | 149.609 |
| KeyFeeder 逻辑，存储黑盒 | 18,905.418 | 未取得 |
| BlockScheduler | 21,387.198 | 28.147 |
| 128 KiB SRAM 宏模型 | 807,686.656 | 43.464，仅漏电 |
| **组件面积合计 / 已覆盖功耗小计** | **1,806,190.806 = 1.806 mm²** | **862.406 = 0.862 W** |

SRAM 按 16 bank × 每 bank 16 个 `256×16` 宏模型组织，共 256 个宏。旧模型把 128 KiB 当成统一端口存储，估计 0.525 mm²；本轮按逻辑深度逐 bank 计算为 0.808 mm²。宏是解析模型，尚未完成实际 SRAM 宏映射，深度译码与选择开销也未完全覆盖。

| 相同功耗假设 | 固定基线 | FAST 硬件 | 随机硬件 |
|---|---:|---:|---:|
| 组件面积合计 mm² | 1.928 | 1.806 | 2.745 |
| α=0.10，已覆盖功耗 W | 1.046 | 0.862 | 1.870 |

FAST 硬件在 α=0.05、0.10、0.20 下的功耗小计分别为 **0.779、0.862、1.019 W**。这是活动假设敏感性分析，不是测量置信区间，也不是整机上下界。未包含 KeyFeeder 逻辑功耗、SRAM 动态读写、DMA、完整控制、时钟树和布线等开销。固定基线是 FAST 的明确固定重构配置，不等同于原论文完整芯片；随机硬件使用 256 PE，FAST 与固定基线使用 128 PE。

调度器在 α=0.10 下的条件能耗估计为 **33.62 nJ/该调度任务**，由 28.1471 mW × 1.194286 μs 得到。这个数不能当作一次 attention 的能耗。

**整机约束仍有未通过或未验证的部分**

RePE、TopK、除法器与调度器在各自独立 STA 中达到 350 MHz；预测阵列的控制广播出现高扇出，报告 slack=-14.6485 ns，单个 NOR2 延迟被外推到 12.8891 ns，触发可信性检查。此结果说明当前未缓冲的综合网表尚未得到有效时序闭合，不能直接给出整机 Fmax，也不能把该失败忽略。KeyFeeder 含未映射存储黑盒，其 STA 尚未完成。

因此，1.806 mm² 只是组件面积清单，不能宣称完整系统已经满足 4 mm² 约束；350 MHz 只对已通过的独立模块成立；整机功耗、完整任务延迟和能耗在 `summary.json` 中明确保留为 null。

旧 L1 模型在相同前 16 个窗口下，给最终点的坐标约为 171.176 μs / 65.188 μJ，能耗仅包含原执行阵列动态模型与原 SRAM 漏电模型。这个模型尚未吸收本轮全部 PPA 校准，也没有覆盖集成开销，不能作为实证 Pareto 点。基线、原 FAST、随机点在此次质量门下被拒绝，不能用它们较低的模型延迟证明有效性能优势。此前等初始预算实验中随机模型前沿还优于 LLM；本轮没有重做多种子、等总成本搜索，不宣称 LLM 优于随机。

**本轮修改及下一步**

工程已修正 schedule 导出丢失硬件参数的问题，使 rows/PE/寄存器/SRAM/queue/bank/divider/M/N 都来自搜索结果；频率验收改为目标周期下的 setup slack；新增按实际参数展开的组件清单、独立 bank SRAM 计量、活动假设敏感性分析、质量分区确认和可复现汇总脚本。

下一步最优先的是修复预测阵列控制广播的扇出并完成缓冲/布局后的 STA，然后将动态阈值选择、真实稀疏索引、KeyFeeder 反压、计算阵列接入同一 harness。最后用该系统的 Q8.8 输出与原 DynaX 对齐质量，采集实际活动轨迹，取得同一任务的总能量与总延迟，再比较等预算随机/固定/LLM 的 Pareto 前沿。当前证据支持“能够发现不合格配置并进行可追溯的参数适配”，尚不支持“已替代算法专家的全栈优化”。
